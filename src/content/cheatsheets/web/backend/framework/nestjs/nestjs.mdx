# 🎯 NestJS — Complete Cheatsheet 🎯

NestJS es un framework progresivo para Node.js diseñado para construir aplicaciones backend escalables, mantenibles y altamente testeables. Inspirado en [Angular](/web/frontend/framework/angular "Angular es un framework de desarrollo de aplicaciones web de código abierto, desarrollado por Google, para construir aplicaciones de una sola página (SPA) y aplicaciones móviles de alto rendimiento."), utiliza [TypeScript](/web/general/typescript "TypeScript es una herramienta fundamental en el desarrollo web moderno, especialmente para proyectos a gran escala, ya que añade seguridad de tipo y mejoras en la productividad.") por defecto, inyección de dependencias nativa y una arquitectura modular basada en decoradores. Soporta Express y Fastify como motores HTTP, e incluye un pipeline de ejecución predecible para validación, autorización, transformación y manejo de errores. Este cheatsheet cubre desde la estructura fundamental y CLI hasta inyección de dependencias avanzada, validación con `class-validator`, testing con `@nestjs/testing`, módulos dinámicos y patrones de producción. Ideal para desarrolladores que migran desde Express, [Django](/web/backend/framework/django/django "Django es un framework web de alto nivel en Python que fomenta el desarrollo rápido y un diseño limpio y pragmático.") o [Spring Boot](/web/backend/framework/spring/spring-boot "¡Absolutamente! Spring Boot es un framework increíble para construir aplicaciones Java robustas y de alto rendimiento de manera rápida y eficiente.") y buscan un stack backend estructurado, tipado y listo para empresa.

## 1. 🌟 Conceptos Fundamentales

* **Arquitectura Modular**: Todo gira en torno a `@Module()`. Cada feature es un módulo autocontenido con controllers, providers y imports específicos.
* **Inyección de Dependencias (DI)**: Sistema nativo basado en contenedores. Los providers se registran, resuelven y gestionan automáticamente. Soporta singletons, factories y scopes.
* **Pipeline de Request Determinista**: Cada petición pasa por capas predefinidas: `Middleware → Guards → Interceptors → Pipes → Controller → Interceptors → Exception Filters`.
* **TypeScript First**: Decoradores, interfaces y tipos estrictos son el estándar. Sin TS, pierdes validación automática, generación de SDK y DX optimizada.
* **Abstracción de Plataforma**: Cambia de Express a Fastify con una sola línea (`FastifyAdapter`). La lógica de negocio permanece intacta.
* **Decoradores como Metadatos**: `@Injectable()`, `@Controller()`, `@Get()`, `@Param()`, `@Body()` inyectan contexto sin acoplar código a `req`/`res` crudos.

## 2. 🛠️ CLI, Instalación y Estructura

* **Instalación global**:
  ```bash
  npm i -g @nestjs/cli
  nest new my-api --strict --package-manager npm
  ```
* **Comandos CLI esenciales**:
  | Comando | Función |
  |---------|---------|
  | `nest start --watch` | Dev server con hot-reload |
  | `nest build` | Compilación a `dist/` (webpack por defecto) |
  | `nest g module users` | Genera módulo + registro en `app.module` |
  | `nest g controller users` | Genera controller con tests |
  | `nest g service users` | Genera provider inyectable |
  | `nest g class dto/create-user` | Genera clase TypeScript pura |

* **Estructura recomendada (Feature-Driven)**:
  ```text
  src/
  ├── main.ts
  ├── app.module.ts
  ├── common/                 # Pipes, guards, filters, interceptors globales
  ├── config/                 # Entornos, validación de .env
  └── modules/
      ├── users/
      │   ├── users.module.ts
      │   ├── users.controller.ts
      │   ├── users.service.ts
      │   ├── dto/
      │   ├── interfaces/
      │   └── entities/       # TypeORM/Prisma/Mongoose
      └── auth/
  ```

## 3. 📝 Arquitectura Base

### 3.1. Módulos
```ts
// users.module.ts
import { Module } from '@nestjs/common';
import { UsersController } from './users.controller';
import { UsersService } from './users.service';
import { PrismaModule } from '../prisma/prisma.module';

@Module({
  imports: [PrismaModule],
  controllers: [UsersController],
  providers: [UsersService],
  exports: [UsersService], // Disponible para otros módulos
})
export class UsersModule {}
```

### 3.2. Controllers
```ts
// users.controller.ts
import { Controller, Get, Post, Body, Param, Query } from '@nestjs/common';
import { UsersService } from './users.service';
import { CreateUserDto } from './dto/create-user.dto';

@Controller('users')
export class UsersController {
  constructor(private readonly usersService: UsersService) {}

  @Post()
  create(@Body() createUserDto: CreateUserDto) {
    return this.usersService.create(createUserDto);
  }

  @Get(':id')
  findOne(@Param('id') id: string) {
    return this.usersService.findOne(+id);
  }

  @Get()
  findAll(@Query('page') page: number = 1, @Query('limit') limit: number = 20) {
    return this.usersService.findAll({ page, limit });
  }
}
```

### 3.3. Providers / Services
```ts
// users.service.ts
import { Injectable, NotFoundException } from '@nestjs/common';
import { PrismaService } from '../prisma/prisma.service';
import { CreateUserDto } from './dto/create-user.dto';

@Injectable()
export class UsersService {
  constructor(private prisma: PrismaService) {}

  async create(dto: CreateUserDto) {
    return this.prisma.user.create({ data: dto });
  }

  async findOne(id: number) {
    const user = await this.prisma.user.findUnique({ where: { id } });
    if (!user) throw new NotFoundException(`User ${id} not found`);
    return user;
  }
}
```

## 4. 🔌 Pipeline de Ejecución (Orden Estricto)

| Capa | Decorador/Clase | Propósito | Ejecuta en |
|------|----------------|-----------|------------|
| **Middleware** | `app.use()`, `NestMiddleware` | Logging, CORS, parsing | Antes de routing |
| **Guards** | `@Injectable() + @CanActivate()` | Auth, roles, permisos | Antes de handler |
| **Interceptors** | `@NestInterceptor` | Transformación, caché, timing, logging | Antes y después |
| **Pipes** | `@Injectable() + @PipeTransform()` | Validación, sanitización, type casting | Antes de parámetros |
| **Controller** | `@Controller()`, `@Get()` | Routing y respuesta | Core handler |
| **Exception Filters** | `@Catch()` | Manejo centralizado de errores | Si lanza excepción |

### Ejemplo Interceptor
```ts
import { CallHandler, ExecutionContext, Injectable, NestInterceptor } from '@nestjs/common';
import { Observable, tap } from 'rxjs';

@Injectable()
export class LoggingInterceptor implements NestInterceptor {
  intercept(context: ExecutionContext, next: CallHandler): Observable<any> {
    const now = Date.now();
    return next.handle().pipe(tap(() =&gt; console.log(`Execution time: ${Date.now() - now}ms`)));
  }
}
// Uso: @UseInterceptors(LoggingInterceptor) o app.useGlobalInterceptors()
```

### Ejemplo Guard
```ts
import { Injectable, CanActivate, ExecutionContext, UnauthorizedException } from '@nestjs/common';

@Injectable()
export class RolesGuard implements CanActivate {
  canActivate(context: ExecutionContext): boolean {
    const request = context.switchToHttp().getRequest();
    if (!request.user?.roles?.includes('admin')) throw new UnauthorizedException();
    return true;
  }
}
```

## 5. 🛡️ Validación, DTOs y Pipes Globales

```ts
// dto/create-user.dto.ts
import { IsString, IsEmail, MinLength, IsOptional } from 'class-validator';

export class CreateUserDto {
  @IsString()
  @MinLength(3)
  username: string;

  @IsEmail()
  email: string;

  @IsOptional()
  @IsString()
  bio?: string;
}
```

* **Activación global (en `main.ts`)**:
  ```ts
  import { ValidationPipe } from '@nestjs/common';
  
  async function bootstrap() {
    const app = await NestFactory.create(AppModule);
    app.useGlobalPipes(new ValidationPipe({
      whitelist: true,                  // Elimina campos no definidos en DTO
      forbidNonWhitelisted: true,       // Lanza error si hay campos extra
      transform: true,                  // Convierte payloads a instancias DTO
      transformOptions: { enableImplicitConversion: true },
      disableErrorMessages: false,      // true en producción
    }));
    await app.listen(3000);
  }
  ```

* **Validación de objetos anidados**: Usa `@ValidateNested()` + `@Type(() =&gt; NestedDto)` (requiere `class-transformer`).

## 6. 🌐 Inyección de Dependencias y Módulos Dinámicos

### 6.1. Custom Providers
```ts
@Module({
  providers: [
    { provide: 'CONFIG', useValue: { dbUrl: process.env.DATABASE_URL } },
    { provide: LoggerService, useClass: WinstonLogger },
    {
      provide: 'ASYNC_CONFIG',
      useFactory: async (config: ConfigService) =&gt; ({ apiKey: await config.get('API_KEY') }),
      inject: [ConfigService],
    }
  ],
})
export class SharedModule {}
```

### 6.2. Módulos Dinámicos (`forRoot`)
```ts
// database.module.ts
import { DynamicModule, Module } from '@nestjs/common';

@Module({})
export class DatabaseModule {
  static forRoot(options: { url: string }): DynamicModule {
    return {
      module: DatabaseModule,
      providers: [{ provide: 'DB_OPTIONS', useValue: options }],
      exports: ['DB_OPTIONS'],
    };
  }
}
// Uso: DatabaseModule.forRoot({ url: process.env.DB_URL })
```

### 6.3. Scope de Proveedor
```ts
@Injectable({ scope: Scope.REQUEST }) // Nuevo por request (websockets/GraphQL)
@Injectable({ scope: Scope.TRANSIENT }) // Nuevo por inyección
```

## 7. 🗄️ Integración con Base de Datos (Prisma/TypeORM)

* **Patrón recomendado**: `PrismaService` como provider global, inyectado en servicios.
* **No exponer entidades en responses**: Usa DTOs de salida (`@Exclude()`, `@Expose()` con `class-transformer`).
* **Transacciones**:
  ```ts
  await this.prisma.$transaction(async (tx) =&gt; {
    const user = await tx.user.create({ data: dto });
    await tx.profile.create({ data: { userId: user.id, bio: dto.bio } });
  });
  ```
* **Lazy vs Eager**: `include: { posts: true }` en [Prisma](/base_datos/orm/prisma "Prisma ORM es un toolkit de base de datos de próxima generación para Node.js y TypeScript que adopta un enfoque schema-first: un único archivo schema.prisma define el modelo de datos, las relaciones, las validaciones y la fuente de datos, y a partir de él se genera automáticamente un cliente tipado (PrismaClient).") evita N+1 queries. En TypeORM usa `@RelationId` o `QueryBuilder`.

## 8. 🧪 Testing y Configuración

### 8.1. Unit Testing (`@nestjs/testing`)
```ts
import { Test, TestingModule } from '@nestjs/testing';
import { UsersService } from './users.service';
import { PrismaService } from '../prisma/prisma.service';

describe('UsersService', () =&gt; {
  let service: UsersService;
  let prisma: PrismaService;

  beforeEach(async () =&gt; {
    const module: TestingModule = await Test.createTestingModule({
      providers: [
        UsersService,
        { provide: PrismaService, useValue: { user: { create: jest.fn(), findUnique: jest.fn() } } }
      ],
    }).compile();

    service = module.get<UsersService>(UsersService);
    prisma = module.get<PrismaService>(PrismaService);
  });

  it('should create a user', async () =&gt; {
    jest.spyOn(prisma.user, 'create').mockResolvedValue({ id: 1, username: 'test' } as any);
    const result = await service.create({ username: 'test', email: 'a@b.com' });
    expect(result.id).toBe(1);
  });
});
```

### 8.2. E2E Testing
```ts
import { Test } from '@nestjs/testing';
import * as request from 'supertest';
import { AppModule } from './../src/app.module';

describe('AppController (e2e)', () =&gt; {

```

## 9. ⚠️ Errores Comunes y Trampas

* **Usar `@Res()` sin `passthrough: true`**: Desactiva interceptors, pipes y manejo automático de status codes.
  * Fix: Devuelve objetos puros desde el controller. Usa `@Res({ passthrough: true })` solo para headers/cookies custom.
* **Validación sin `ValidationPipe` global**: Los DTOs no se instancian, `class-validator` ignora decoradores.
  * Fix: `app.useGlobalPipes(new ValidationPipe({ transform: true }))` en `main.ts`.
* **Dependencias circulares entre módulos**: `A imports B`, `B imports A` → fallo en arranque.
  * Fix: Usa `forwardRef(() =&gt; ModuleB)` o extrae providers a un módulo compartido.
* **Exponer contraseñas o campos sensibles**: Entidades de DB van directo al response.
  * Fix: Usa `@Exclude()` en entidades o mapea a DTOs de salida explícitos.
* **No manejar `NotFoundException` vs `BadRequestException`**: Errores genéricos confunden clientes.
  * Fix: Lanza excepciones HTTP específicas de `@nestjs/common`. Usa `@Catch()` para normalizar formato.
* **Middleware asíncrono sin `await`**: `app.use()` espera `req, res, next`. Si usas async, llama `next()` manualmente.
  * Fix: Usa `NestMiddleware` con `async use(req, res, next)` y `await` + `next()`.

## 10. 💡 Mejores Prácticas y Consejos de Experto

* **Arquitectura por features, no por capas**: Agrupa `users/`, `payments/`, `auth/` con sus propios controllers, services, DTOs y entities. Facilita escalado y ownership.
* **Pipes + Guards + Interceptors = Separation of Concerns**: Validación en pipes, autorización en guards, logging/caché/timing en interceptors. Nunca mezcles lógica cross-cutting en controllers.
* **Usa `class-validator` con `Zod` o `Joi` solo si es estricto necesario**: `class-validator` + `class-transformer` es nativo, pero `zod` + `zod-validation-pipe` gana en type safety moderno.
* **Health checks con `@nestjs/terminus`**: Expone `/health` con checks de DB, [Redis](/base_datos/nosql/redis "Redis es un almacén de datos en memoria, de código abierto y alto rendimiento, que actúa como base de datos, caché, broker de mensajes y motor de streaming."), memoria y disco. Integración nativa con [Kubernetes](/devops/kubernetes "Kubernetes (K8s) es una plataforma portable y extensible de código abierto para gestionar cargas de trabajo y servicios en contenedores.")/[Docker](/devops/docker "Docker es una plataforma de código abierto que utiliza la contenerización para empaquetar una aplicación y todas sus dependencias en una unidad estándar para el desarrollo de software.").
* **Documentación automática con `@nestjs/swagger`**: `@ApiProperty()`, `@ApiOperation()`, `@ApiResponse()` generan [OpenAPI](/herramientas/openapi "OpenAPI Specification (OAS) es un formato de descripción de API es un conjunto de reglas, protocolos y herramientas que permite que diferentes aplicaciones de software se comuniquen entre sí.') estándar, independiente del lenguaje, legible tanto por humanos como por máquinas.") completo. Ideal para SDKs cliente y contratos frontend.
* **Perfila con `clinic.js` o `0x`**: NestJS es rápido, pero tu lógica de DB o serialización puede ser el cuello. Mide antes de optimizar.
* **Logging estructurado**: Reemplaza `console.log` con `@nestjs/common/Logger` o integra `pino`/`winston` vía `app.useLogger()`.
* **Evita `any` y `Object`**: Usa interfaces, DTOs y `Record<string, unknown>` estricto. TypeScript es tu principal validador en compilación.
* **CI/CD con `tsc --noEmit` + `eslint` + `jest`**: Valida tipos, linting y cobertura antes de merge. Usa `tsconfig-paths` para imports absolutos limpios (`@/modules/users`).
* **Despliegue optimizado**: `nest build` genera `dist/`. Usa `node --max-old-space-size=512` para limitar memoria. Prefiere PM2 o Docker con healthchecks.
